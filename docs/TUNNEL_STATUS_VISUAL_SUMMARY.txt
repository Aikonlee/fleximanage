┌──────────────────────────────────────────────────────────────────────────────┐
│                        🔄 TOPOLOGY 1: FULL-MESH                              │
└──────────────────────────────────────────────────────────────────────────────┘

  Status: ✅ ALL READY!

  Topology Diagram:
  ┌─────────────────────────────────────────────────┐
  │                                                 │
  │         Device A ←────────→ Device B            │
  │             ↑      \    /      ↑                │
  │             │       \  /       │                │
  │             │        \/        │                │
  │             │        /\        │                │
  │             │       /  \       │                │
  │             ↓      /    \      ↓                │
  │         Device C ←────────→ Device D            │
  │                                                 │
  │         All devices interconnected!             │
  └─────────────────────────────────────────────────┘

  Formula: n × (n-1) / 2 tunnels
  
  Examples:
    • 2 devices  =  1 tunnel
    • 3 devices  =  3 tunnels
    • 4 devices  =  6 tunnels  ✅ TESTED
    • 5 devices  = 10 tunnels
    • 10 devices = 45 tunnels

  Use Cases:
    ✓ Small networks (2-10 devices)
    ✓ High availability requirements
    ✓ Low latency needs (direct paths)
    ✓ No single point of failure
    ✓ Frequent inter-site communication

  Technical Specs:
    • Protocol      : IPSec over VxLAN
    • Port          : UDP 4789 (VxLAN)
    • Routing       : OSPF (default) or BGP
    • Encryption    : PSK or IKEv2
    • Loopback IPs  : 10.100.0.0/16
    • NAT Support   : Full Cone, Restricted, Port-Restricted


┌──────────────────────────────────────────────────────────────────────────────┐
│                      🌟 TOPOLOGY 2: HUB-AND-SPOKE                            │
└──────────────────────────────────────────────────────────────────────────────┘

  Status: ✅ ALL READY!

  Topology Diagram:
  ┌─────────────────────────────────────────────────┐
  │                                                 │
  │                    HUB                          │
  │                 (Device 1)                      │
  │                     │                           │
  │            ┌────────┼────────┐                  │
  │            │        │        │                  │
  │            ↓        ↓        ↓                  │
  │         Spoke A  Spoke B  Spoke C               │
  │        (Dev 2)  (Dev 3)  (Dev 4)                │
  │                                                 │
  │     Spokes communicate through Hub              │
  └─────────────────────────────────────────────────┘

  Formula: n - 1 tunnels (n = total devices)
  
  Examples:
    • 2 devices (1 hub + 1 spoke) = 1 tunnel
    • 3 devices (1 hub + 2 spoke) = 2 tunnels
    • 4 devices (1 hub + 3 spoke) = 3 tunnels  ✅ TESTED
    • 5 devices (1 hub + 4 spoke) = 4 tunnels
    • 11 devices (1 hub + 10 spoke) = 10 tunnels

  Use Cases:
    ✓ Large networks (10+ devices)
    ✓ Centralized management
    ✓ Cost optimization (fewer tunnels)
    ✓ Central datacenter architecture
    ✓ Branch offices to HQ connection

  Technical Specs:
    • Protocol      : IPSec over VxLAN
    • Port          : UDP 4789 (VxLAN)
    • Routing       : OSPF (default) or BGP
    • Encryption    : PSK or IKEv2
    • Hub Selection : First device in selection
    • Traffic Flow  : Spoke → Hub → Spoke

  Step 1: Login

    Click "Create Tunnels" button (top right)
    
  Step 5: Choose Topology
    ○ Full Mesh      - All devices interconnected
    ○ Hub and Spoke  - Star topology with central hub
    
  Step 6: Confirm

    ⏱ Wait 30-60 seconds for tunnel creation
    
  Step 8: Verify
    Navigate to "Tunnels" page
    All tunnels should show "Connected" status ✅


┌──────────────────────────────────────────────────────────────────────────────┐
│                           🔌 API USAGE                                       │
└──────────────────────────────────────────────────────────────────────────────┘

  Endpoint: POST /devices/apply
  
  Authentication: Bearer Token
  
  Request Body Structure:
  {
    "method": "tunnels",
    "devices": {
      "device_id_1": true,
      "device_id_2": true,
      "device_id_3": true,
      "device_id_4": true
    },
    "meta": {
      "tunnelType": "site-to-site",
      "pathLabels": [],
      "topology": "fullMesh",        // or "hubAndSpoke"
      "hub": null,                   // or "hub_device_id" for hub-spoke
      "advancedOptions": {
        "routing": "ospf"            // or "bgp"
      }
    }
  }
  
  Response:
    200 OK - Tunnels are being created
    400 Bad Request - Invalid parameters
    401 Unauthorized - Invalid token
    500 Internal Server Error - Server error

│                        ✅ VERIFICATION CHECKLIST                             │
└──────────────────────────────────────────────────────────────────────────────┘

  Before Creating Tunnels:
    ☑ All devices are online (Connected)
    ☑ vRouter status is "Running"
    ☑ At least 1 WAN interface per device
    ☑ Devices have compatible router versions
    ☑ Organization has encryption method configured
    ☑ Firewall allows UDP 4789, 500, 4500
  
  After Creating Tunnels:
    ☑ Check Tunnels page for new tunnels
    ☑ Verify tunnel status shows "Connected"
    ☑ Test network connectivity between LANs
    ☑ Check OSPF neighbors (if using OSPF)
    ☑ Verify routes in device routing table
    ☑ Monitor backend logs for errors
